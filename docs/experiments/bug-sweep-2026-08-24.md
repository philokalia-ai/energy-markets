# Bug sweep 2026-08-24 (cv33)

Owner request: "launch a thorough investigation fixing bugs" (2026-08-24, right
after the rule reset in #341). Scope taken: the price-producing paths — `src/`
(book build, flows, network, clearing, MPCC, DB layer) and the daily forecast
path in `bin/` — verified by reproducing each defect before touching code. Six
parallel read-only reviewers (one per area) produced ~60 candidates; every item
below marked FIXED was reproduced by me on live Postgres or the public extract
first. No new mechanism ships here: the sweep is input-side and record-integrity
only, so it is versioned as **cv33** (the cv34 prereg draft had left 33 unused;
taken because these fixes precede the collapse package — renumber if you object).

Budget: one find pass + one verify/fix pass, this session. Everything not fixed
is listed under *Deferred* with the reason, one paragraph each.

## Fixed (with the measured defect)

### Generator registry — `src/generators/registry.jl`

1. **Superseded/cancelled outage versions were applied.** ENTSO-E versions every
   outage message (`instance_code` × `version`); a cancellation or end-date
   change is a NEW row and the superseded rows keep `status='Active'` with
   `old_version=true`. The day-outage query filtered on status only. Live
   Postgres 2026-04-03: assets removed/derated by a superseded version only —
   FR 31 units / 16.0 GW, DE_LU 32 / 9.1 GW, ES 20 / 5.7 GW, PL 17 / 5.4 GW,
   IT-NORTH 7 / 4.0 GW, CH 9 / 3.7 GW (since 2026-01: 745k Active rows, 647k
   of them superseded). Fix: `AND NOT old_version`. **Net fleet effect is much
   smaller than the headline** because the 7-day "generated during its outage"
   override was already rescuing most of these units: FR 2026-04-03 fleet
   diff main→fix = 8 units / +392 MW restored, 3 units / −1,117 MW newly
   removed (item 2), 3 derates corrected (net −102 MW).
2. **Outage overlap was tested at a single instant (D 00:00 UTC).** An outage
   starting 06:00 on D was ignored for all of D; one ending 00:30 on D excluded
   the unit for 24 h (reviewer scan Mar–Apr 2026: ~71 asset-days/day missed,
   ~18 GW nameplate; ~15/day over-applied). Fix: the outage counts when it covers
   ≥ 12 of the day's 24 hours (p_max is a day-level quantity).
3. **Stale-outage override probe started at the earliest row of ANY record**, so
   generation during an old partial derate "proved wrong" a full outage that
   began later. Fix: the probe starts at the binding (0-MW) record.
4. **Outages matched on the outage table's own area code.** Italian units filed
   under `IT` or another sub-zone never reached the registry's zone (reviewer:
   IT-CNORTH 1.24 GW, IT-CSOUTH 1.07 GW of Active outage never applied). Fix:
   the day table is grouped by `asset_code` alone and every zone's query joins
   on it.
5. **`DISTINCT ON` preferred a FUTURE-valid registry row.** `ORDER BY valid_from
   DESC` let a row with `valid_from` after the day win. IT-CSOUTH
   `26WUUUUUUBUSSI19`: correct 122 MW row valid 2022-12-20..2025-12-31, corrupt
   13,068,005 MW rows from 2025-12-31 — the corrupt row won on every date, and
   the cv24 plausibility bound then dropped the unit entirely. Fix: the row whose
   validity covers the day sorts first; IT-CSOUTH 2026-04-03 fleet 9,969 →
   9,386 MW (the corrupt row is gone, the real unit is back).
6. **Partial-outage capacity above installed inflated p_max** (no `LEAST`). Fix.

### Cost model — `src/generators/fuel_costs.jl`

7. **`Fossil Oil shale` (EE, 2.25 GW), `Fossil Peat` (FI/SE3, 1.28 GW) and
   `Other renewable` were priced at the gas-like default with ZERO carbon**
   (€79.3 flat). Fix: named entries — oil shale SRMC 103.9, peat 115.6 €/MWh at
   2026-04-03 EUA (base 30/45 + EF 1.10/1.05 tCO₂/MWh_el); other renewable 45.

### RES forecast input — `src/Renewables.jl`

8. **NULL day-ahead values threw (SEE path) or became 0 MW (EU path).** 17,096
   NULL rows in the 2023-26 extract (PL Jun-2026 wind+solar 15 days, ES, SE1-4,
   DK1/2, IT-*). SEE path: RS 2026-04-03 (22/24 wind rows NULL) was DROPPED from
   the coupled clear with a warning — the test suite had been running with 4
   zones. EU path: ES 2026-06-11 (16/192 values present) cleared 167.5 vs 32.8
   settled (record MAE 134.7); FI 2026-04-03 111.8 vs 43.4; IT-* 2026-04-03 —
   the parity-guard day cleared with essentially no RES in IT/FI/SE. Fix: a
   NULL takes the zone/type's most recent published value at the same
   time-of-day within 7 days (persistence, ex-ante), else the nearest published
   value in the day, else 0 — always logged, never thrown. Measured: RS
   2026-04-03 22 filled; ES 2026-06-11 176 filled (noon 30.8 GW); DK1
   2025-04-09 243 filled.
9. **Mixed 15/60-min rows for the same production type were double- or
   quarter-counted.** Downstream took the resolution of the first row: PT60M
   first → the hourly row was summed on top of its quarters (2-5×); PT15M
   first → only the :00 quarter survived the hourly aggregation (¼). 19
   footprint zone-days (FR 2026-01-06..08, GR 2025-10-08, LT 2024-10-08..11,
   SE1-4 2025-11-23/24, SI 2026-05-19, SK 2026-04-28); FR 2026-01-08 record
   mean 63.5 vs 109.9 settled, DE_LU MAE 8.8 → 40.6 the same day. Fix: one
   resolution per type (most hours covered, tie → coarser), finer types
   averaged to the coarsest over known values only. Measured FR 2026-01-08
   noon RES 16.2 GW (was 7.0 or ~32); GR 2025-10-08 4.0 GW; SE3 2025-11-24
   432 MW with 138 NULL quarters carried from the published :00 values.

### Book / profile — `src/merit_order/zone_profiles.jl`

10. `ZoneProfile.input_corrections` had no `FIELD_DESCRIPTIONS` entry → the
    generated strategy table and the PROVENANCE export omitted it (3 suite
    failures). Fix: description added.

### Clearing — `src/clearing/multi_zone_run.jl`

11. **Pass-2 rebuild ignored the `ex_ante_mode` kwarg** — A/B arms driven by the
    kwarg cleared pass 1 in the requested mode and the anchored zones' pass 2
    in the env/scoped default (mixed-mode books). Record path unaffected
    (kwarg `nothing`). Fix: forwarded.
12. **Sequential save path had no truncation gate** — a zone with a short
    load forecast collapses the coupled intersection for all 39 and the
    date-range runners treat any saved row as done (the cv24 65-day defect,
    still live for `bin/reproduce.jl` non-pipeline and `multi_zone_main.jl`).
    Fix: `min_price_periods=24` gate, same as the pipeline.

### MPCC price reconstruction — `src/mpcc/solver.jl`

13. **Rent-sign fallback was period-wide**: one violated link reverted every
    zone's price for that hour to the solver's arbitrary bracket point (the
    documented cv25 defect). Fix: per-component bracket `[lo, hi]`; an unpinned
    component is moved within its bracket to satisfy binding links; only the
    components that cannot be reconciled keep the solver's prices
    (`fallback_cells` counted and warned).
14. **Acceptance tolerance was relative (1e-4 × Q)**: up to 6 MW of a 60 GW
    price-taker block could be curtailed and read as "fully accepted", so a
    genuine scarcity hour was priced at the top accepted supply instead of the
    cap. Fix: MW tolerance (0.5 MW).
15. **Zero-quantity orders constrained the bracket** and an inverted bracket
    (`lo > hi`) was silently clamped. Fix: skipped / counted and warned.
    `test/test_price_reconstruction.jl`: 22/22 (five new regression tests).

### Result stores — `src/db/results_store.jl`, `src/db/duckdb_store.jl`, callers

16. **`optimization_runs` and `transmission_flows` were written with a
    hard-coded `code_version=4` and flows had no `clearing_mode`.** Live
    Postgres: flows 100% cv4 (2.46M rows); the SEE 5-zone daily job and the EU
    record upserted the same `(dt, GR, BG, 4)` key; `optimization_runs` cv ∈
    {1,2,3,4,6} so cv22/23/24 prices all point at the run that wrote last; the
    cv31 record's flows never reached Postgres (the transfer read flows at the
    price cv). Under DuckDB the flows writer deleted EVERY flow row of the day
    before inserting (a 5-zone run wiped the 39-zone flows). Fix: both writers
    default to `ENERGY_PRICES_CODE_VERSION`; `transmission_flows` gains
    `clearing_mode` (Postgres migration: column + re-keyed unique constraint;
    DuckDB `ADD COLUMN IF NOT EXISTS`; legacy rows labelled `multi_zone`); the
    DuckDB delete is scoped to `(day, cv, clearing_mode)`; all three callers
    pass the label. Verified: 5-zone clear on the extract → 48 flow rows under
    `bugsweep_see`/cv32 (`optimization_runs` cv32 too).
17. **`bin/transfer_results_to_postgres.jl` with the default (unbounded) window
    deleted the ENTIRE Postgres `(clearing_mode, cv)` slice** and restored only
    what the source held — and `--verify` compared the two sides AFTER the wipe,
    so it passed. Fix: the window is bounded to the source slice's own
    `MIN/MAX(date)`; flows transferred and deleted by `clearing_mode` too.

### Daily forecast — `bin/`

18. `atc_row_count` fell back to the all-rows count when no Day-ahead rows
    existed — exactly the "only Intraday rows have landed" case the gate exists
    to block. Fix: DA rows only (warns when only non-DA rows exist).
19. A NaN ML wind/solar prediction was mapped to 0 MW and the hour counted as
    covered (zone cleared with zero RES, silently). Fix: the hour is left
    uncovered so `res_covered_for_day` triggers the fallback.
20. `score_forecasts.jl` persisted scores for any n ≥ 1 paired hours (IT-*
    scored on a single 21:00 hour, then frozen by the NOT-EXISTS discovery).
    Fix: `MIN_SCORE_HOURS=12` (env-tunable); short days are rescored when the
    actuals complete.
21. A partial live slice was deleted and rewritten in full with a NEW
    `prediction_made_utc` (the 08:00 re-run destroyed the 06:49 vintage of the
    38 frozen zones). Fix: only the missing zones are written; the LIVE delete
    is scoped to the zones being written.

## Deferred (real, not fixed here — one paragraph each)

- **Same-day outage publications are applied (lookahead).** The unavailability
  table carries `version_publication_timestamp_utc` but the query never uses
  it; on 2026-04-03 assets first published after D-1 10:00 UTC: DE_LU 1.94 GW,
  GR 837 MW, RS 349 MW. Before ~Oct 2025 the column holds ETL ingestion time,
  so a vintage filter is only honest for the live period — applying it creates
  a discontinuity in the record. Owner decision.
- **TTF/EUA use the D-1 close** (`date < D`), which does not exist at the D-1
  12:00 CET gate; the gate-honest price is D-2's (mean |Δ| 2.3 €/MWh_el on gas
  SRMC, p90 4.9). Design choice; owner decision.
- **`entsoe` track leads 2-7 are weekly-persistence copies of the T-7 lead-1
  slice** (`bin/horizon_forecast.jl`), stamped `input_mode='entsoe'`,
  `clearing_mode='multi_zone_eu'` and the CURRENT cv, with no distinguishing
  column — the per-lead board compares the weather track's genuine lead-n
  clear against a relabelled lead-1 (936/936 rows identical, shifted 7 d).
  Needs a label decision (a distinct `input_mode` or an `is_persistence`
  column) because the site's track switch keys on `input_mode`.
- **Retro reconstruction is vintage-honest only for weather**: D-2 flows,
  analogue pool, TTF/EUA, outages, capability windows and the AR load features
  all read data anchored to the delivery day, so retro lead ≥ 2 rows measure
  weather decay with every other input at lead-1 quality; live lead ≥ 2 rows
  feed NaN AR features to LightGBM. Documented convention vs. what the doc
  claims; needs a decision on what the lead ladder is meant to measure.
- **Fleet completion undoes fresh outages**: the type target is the trailing-30d
  p95 (pre-outage output) while `fleet` is the outage-filtered registry, so a
  fresh >1 GW outage is re-added as an `AGG-` unit at SRMC until it has
  persisted ~30 days. A modelling change (outage-aware p95), not a one-line fix.
- **`get_installed_capacity_by_type` has no validity filter** (FR nuclear
  denominator includes Flamanville 3 for 2023 days: `_nuclear_avail_frac` 2.6%
  low; CZ pumped storage with `valid_from` 2027 counted today). Touches the
  `:installed` fleet truth and the FR anchor share — measure before changing.
- **`_endogenous_import_atc` omits the cv27 capability override and border
  drops**, so on cv27 borders touching backstop zones (CH~FR, IT-CNORTH~IT-NORTH,
  DK1~SE3) the backstop is over-sized in Day-ahead-free hours. Consistency
  change with a measurable price effect; needs its own A/B.
- **`can_carry_flow` misses borders whose two directions are published on
  disjoint hours** (both zones keep observed injections AND the MPCC creates
  the flow variable → double count); cv26 notes 0.23% of border-days with
  partial-day DA coverage. Small; fix with a directed-pair test.
- **cv32 wind delta averages Wind Onshore and Wind Offshore** (`AVG` grouped by
  target) while the emitter sums them → +½ total wind when a wind correction is
  consumed. Latent (DK1 `input_corrections=false`); fix before enabling DK1.
- **`get_import_backstop` treats a missing lagged week as 0 net flow** →
  phantom headroom on net exporters when history is short. Unconfirmed
  magnitude.
- `:p95`-books fallback is invisible in the record and the pipeline does not
  implement it (sequential re-clears silently, pipeline fails the day); Gurobi
  retry rung 1 shortens the time limit 900→300 s without flagging; `mip_gap`
  1e-6 relative on a ~1e9 objective leaves sub-200 € tranche flips to solver
  discretion. Provenance/observability items.
- `energy_prices` live UNIQUE constraint includes `optimizer`, which is NULL on
  every row, so it is inert (0 duplicates today); `save_optimization_run`
  swallows errors and callers persist prices with a NULL run id; DuckDB
  `save_optimization_run` delete-then-insert orphaned 4.68M price rows' run ids
  in `data/results.duckdb` (the transfer NULLs them silently).
- `forecast_scores` PK excludes `is_retro`; `input_corrections.date_time_utc`
  is `timestamp` joined to `timestamptz` (correct only because LibPQ pins UTC);
  lead computed from the Athens date vs a CET gate (21:00-24:00 UTC window);
  `run_retro` does not bound `RETRO_ASOF` to realized days; dispatch with
  `pregate=true` ignores `force_rerun`.
- Reservoir-dryness neighbourhood drops ISO week 53; `:v3` blends on Nordic
  borders too although its doc says non-Nordic only (record follows the code).
- Stale tests: `test_zone_profiles.jl` (RS now shares the GR profile; boundary
  books on DK1/HU) and `test_extract_refresh_logic.jl` (2) — pre-existing.
